# 空のイベント（UFO・流星群）ほか — 設計書

- 作成日: 2026-08-07
- 対象: `index.html`（単一ファイル）
- 状態: 設計確定・実装前

## 1. 背景と目的

集中セッション中の画面に、もう少し起伏を作りたい。現状は星・星雲・彗星がセッション開始時に決まるだけで、25分のあいだ新しい出来事が起きない。

同時に、以前から保留していた2件（ファビコン未設定、明るい空でのテキスト可読性）もこの回で解消する。

## 2. スコープ

### 含むもの

1. 空のイベント基盤（稀に起きる出来事を管理する仕組み）
2. UFO
3. 流星群
4. 既存の彗星の挙動修正（無限反復 → 一度きり）
5. ファビコン
6. 中央テキストのコントラスト修正

### 含まないもの（別回で設計する）

- **星座** — 完了セッションが星として残り線で結ばれる。データ構造から設計が必要。次回の第一候補
- **観測レポート** — セッション終了時の報告文
- **ワープ演出** — 4セッション達成時の演出
- オーロラ・日食（基盤には載るが今回は実装しない）

## 3. 確定した設計判断

これらは検討の結果、意図をもって選んだもの。実装時に覆さない。

| 論点 | 決定 | 理由 |
|---|---|---|
| UFO の役割 | 風景＋記録。クリック不可 | クリック要素は集中中に画面を見張る動機を作り、道具の目的と逆行する |
| 頻度と記録の分離 | 通過は頻繁、記録は稀な接近遭遇のみ | 全通過を記録すると Voyage Log が UFO で埋まり、集中記録が読めなくなる |
| 出現条件 | 集中セッション中は明暗を問わず | 深宇宙限定だと頻度が半減し、要望を満たせない |
| 明暗の描き分け | 明→シルエット、暗→発光 | 回避策ではなく演出として成立する。「潜っていく」テーマと噛み合う |
| 機体の形 | 古典的な円盤 | 遊び心を足すという目的に最も素直 |
| コントラスト対処 | チップ方式 | 明るい青空という個性を保ちつつ、機能的に重要な文字を確実に直せる |

## 4. アーキテクチャ

### 4.1 方針

UFO 専用のコードではなく、**空で稀に起きる出来事**を管理する汎用の仕組みを作り、その上に UFO と流星群を載せる。将来オーロラ等を足すときは定義を1つ増やすだけで済む。

### 4.2 描画ループへの組み込み

既存の `drawFrame(now)` の末尾（視差の更新の前）に2行追加する。

```
drawFrame(now)
  ├ 背景グラデーション        （既存）
  ├ 星                        （既存）
  ├ 星雲                      （既存）
  ├ 彗星                      （既存・4.6 で修正）
  ├ updateSkyEvents(dt)       ← 追加
  ├ drawSkyEvents(now, depth) ← 追加
  └ 視差の更新                （既存）
```

### 4.3 イベント定義

```js
const SKY_EVENTS = {
  ufo: {
    gap: [210, 390],              // 次の発生までの秒数の範囲
    canRun: () => true,
    spawn: spawnUfo,
    update: updateUfo,
    draw: drawUfo
  },
  meteors: {
    gap: [300, 600],
    canRun: () => depthFactor() > 0.45,
    spawn: spawnMeteors,
    update: updateMeteors,
    draw: drawMeteors
  }
};
```

### 4.4 状態

```js
let activeEvents = [];   // 進行中のインスタンス（寿命付き）
let nextEventIn = {};    // 種類ごとの、次の発生までの残り秒数
```

### 4.5 スケジューラの規則

1. **`state.mode === "work"` かつ `state.running === true` のときだけ時間を進める**
   停止中・休憩中は残り秒数を減らさない。アプリを開いたまま放置して記録が増えるのを防ぐ。「集中した時間の中で遭遇した」という記録の意味を守るため。
2. 種類の `canRun()` が偽の間も時間を進めない。
3. 残り秒数が 0 以下になったら `spawn()` を呼び、`gap` の範囲から次の待ち時間を引き直す。
4. 進行中のイベントは毎フレーム `update(inst, dt)` を受け、`inst.age > inst.ttl` になったら配列から除く。
5. 初期化時、各種類の残り秒数は `gap` の範囲からランダムに引く（起動直後に必ず出ることを避ける）。
6. **セッションが切り替わったら進行中のイベントを全て破棄する。** 対象は、集中セッションの完了、休憩への遷移、リセット操作。
   このとき、通過途中だった接近遭遇は**記録しない**。記録は 5.4 のとおり画面外へ抜けた時点でのみ発生する。
   セッションをまたいで UFO が飛び続けたり、完了した瞬間に遭遇記録が滑り込んだりするのを防ぐため。

タブが非表示のあいだは `requestAnimationFrame` 自体が止まるため、追加の対処は不要。`dt` は既存コードで 0.05 秒に制限されており、復帰時に大量の時間が一度に進むことはない。

### 4.6 乱数について（重要）

**イベントは `Math.random()` を使い、既存の `rng` には触れない。**

既存の星空はセッションごとの種から作られる再現可能な乱数（[index.html:436-439](../../../index.html)）で構成されている。ここにイベント用の抽選を混ぜると引く順番がずれ、**星空そのものが変わってしまう**。

イベントは「たまたま起きる出来事」であって「その日の空の形」ではないため、性質としても別の乱数源が正しい。

## 5. UFO

### 5.1 2つの型

| | 遠景通過 | 接近遭遇 |
|---|---|---|
| 割合 | 7/8 | **1/8** |
| 幅 | 約 24px | 約 70px |
| 横断時間 | 約 8 秒 | 約 14 秒 |
| 軌道 | 直線 | ゆるい正弦波の揺れ |
| 記録 | 残さない | **Voyage Log に1行** |

発生間隔は 210〜390 秒（平均約 5 分）。25 分のセッションで通過は約 5 回、うち接近遭遇は平均 0.6 回。**約 1.6 セッションに 1 回**の頻度。

比率と間隔は定数1つで調整できるようにし、実際に動かしてから微調整できる状態にしておく。

### 5.2 出現位置と軌道

- 進行方向は左右どちらかをランダムに選ぶ
- 縦位置は画面高の **15〜40% または 65〜85%** の範囲から選ぶ
- 中央帯（40〜65%）を避けるのは、タイマーリングの真後ろを横切ると視認性が落ちるため
- 画面外から入り、画面外へ抜けたら寿命終了

キャンバスは UI の背面（`z-index: 0` に対し `.app` は `2`）にあるため、UFO はリングや Voyage Log パネルの**裏**を通る。これは視差の奥行きとして意図通り。

### 5.3 描画

`drawFrame` で計算済みの `depth`（0=地表、1=深宇宙）をそのまま濃度に使い、2つの描画を重ねてクロスフェードさせる。閾値による切り替えは行わない（不連続な変化を避けるため）。

- **シルエット**（`depth` が小さいほど濃い）: 濃紺 `#06182c` の塗りつぶし。円盤と上部ドームのみ
- **発光機体**（`depth` が大きいほど濃い）: 本体 `--accent` 相当の水色、ドームは白、下部に暖色のライト3点。淡いグロー

形状は古典的な円盤（横長の楕円＋上部の半球ドーム）。

### 5.4 記録の形式

接近遭遇が画面外へ抜けた時点で1行追加する。通過中に追加しないのは、途中でセッションが終わった場合に中途半端な記録が残るのを避けるため。

```js
{ ts: Date.now(), kind: "ufo", name: "Unidentified Craft" }
```

表示は既存のログ行の枠を流用する。

- 左: 名前を `--accent-warm`（暖色）で表示。集中記録の水色と区別する
- 右: `25 min focus` の位置に `sighting` と表示
- 絵文字は使わない（このアプリはアイコンを絵文字から線画に統一した経緯があるため）

## 6. 流星群

| 項目 | 内容 |
|---|---|
| 出現条件 | `depthFactor() > 0.45` |
| 発生間隔 | 300〜600 秒（条件を満たしている間のみ計測） |
| 継続時間 | 約 12 秒 |
| 構成 | 8〜14 本の流星が、継続時間内のばらけたタイミングで流れる |
| 記録 | 残さない |

明るい空を除外するのは、流星が「光の筋」であり、明るい背景では原理的に見えないため。UFO のようにシルエット化することもできない。

**放射点を持たせる。** 画面外の一点を放射点として決め、すべての流星をそこから外向きに流す。実際の流星群がそう見えるため。これがないと「線がランダムに出るだけ」の演出になる。実装コストはほぼ変わらない。

各流星は短く速く、尾がグラデーションで消える。既存の彗星（長く遅い）とは明確に異なる見え方にする。

## 7. 既存コードへの変更

### 7.1 彗星を一度きりにする（挙動変更）

現状、彗星は画面外に出ると位置を戻して**無限に反復する**。

```js
if(comet.progress > 1.3) comet.progress = -0.2;   // 現状
```

深宇宙に入って以降、同じ彗星が往復し続けている。ここに流星群が加わると空が常時ちらつき、流星群の希少性も損なわれる。

反復をやめ、一度通過したら終了とする。彗星本来の希少性も回復する。

### 7.2 集計処理の防御（必須・見落とすと破壊的）

[index.html:400](../../../index.html) の初回集計。

```js
const backfill = loadLog().reduce((sum, e) => sum + e.minutes, 0);   // 現状
```

UFO の記録には `minutes` が存在しない。この行がそれを拾うと `undefined` が加算されて結果が **NaN** となり、総航行距離とマイルストーン表示が全て壊れる。

```js
const backfill = loadLog().reduce((sum, e) => sum + (e.minutes || 0), 0);   // 修正後
```

この処理は `spacetimer.totalFocusMin.v1` が存在しないときだけ走るため、通常のテストをすり抜ける。**後日いきなり壊れる類の不具合**であり、必ず対応する。

### 7.3 ログ描画の分岐

`renderLog()` の各行生成に `kind` による分岐を追加する。`kind` を持たない既存の記録は、これまで通り集中記録として描画する（後方互換）。

## 8. ファビコン

`<head>` に SVG を data URI として1行追加する。外部ファイルを増やさず、単一ファイル構成を維持する。

- 図案: 進行リング（切れ目のある太い輪）
- 色: 中間の水色（`#3aa8d8` 前後）
- 理由: アプリ内の `#7fd8ff` は明るすぎ、白いタブ背景で見えなくなる。タブの地色は明暗どちらもあり得るため、両方で成立する濃さを選ぶ
- `prefers-color-scheme` による追従は、ブラウザ間の対応差があるため採用しない

data URI 内では `#` を `%23` にエスケープする必要がある。

## 9. コントラスト修正

### 9.1 現状（実測値）

明るい空（測定背景 `rgb(105,185,241)`）での実測。基準は WCAG AA の 4.5:1。

| 要素 | 実測 |
|---|---|
| `FOCUS SESSION`（`.session-label`） | 1.34:1 |
| `Observing: <星名>`（`.starname`） | 1.60:1 |
| 設定欄ラベル（`.settings-row`） | 1.82:1 |
| 下部の説明文（`footer.hint`） | 1.77:1 |

### 9.2 検討して却下した案

- **文字色を明るくするだけ** — 明るい空の上では白でも 2.14:1 にしかならない。単一色では不可能
- **depth に応じて文字色を明→暗と変化させる** — 中間の明るさに、どんな色でも 4.5:1 を満たせない領域が存在する。成立しない
- **中央スクリム** — 全4箇所を解決できるが、必要な濃度が 0.55 程度で明るい空が目に見えて暗くなる
- **空の配色自体を暗くする** — 追加要素は不要になるが、開始時の明るい青空という個性が失われる

### 9.3 採用する方式

機能的に重要な2箇所に、左上の読み取り部と同じガラス調のチップを与える。

- `.session-label` — 1行のテキストなので、要素自体に背景・角丸・内側余白を与える
- `.settings-row` — 3つのラベルと入力欄を含む1つの帯。**ラベルごとに分割せず、行全体を1枚のチップで囲む**（3つ並ぶと煩雑になるため）

| 対象 | 適用後（計算値） |
|---|---|
| `.session-label` | 6.59:1 |
| `.settings-row` | 4.92:1 |

既存の `--ui-bg-strong` と現行の文字色のままで基準を満たす。色の変更は不要。

### 9.4 対象外とするもの（意図的）

`.starname` と `footer.hint` は装飾的な文章であり、今回チップを与えない。最も明るい瞬間には基準を下回ったままとなる。

これを許容する理由は、空が1分ほどで暗くなり始め以降は読めるようになること、そして全4箇所を完璧にするには 9.2 で却下した全体的な暗化が必要になり、デザインの意図を損なう代償が見合わないため。

**この判断は意識的なトレードオフであり、見落としではない。**

## 10. 検証方法

推測で報告せず、実測する。

1. **コントラスト** — ヘッドレス Chrome で描画し、出力画像の実ピクセルから比を算出。修正前後を並べて報告
2. **UFO の描き分け** — 明るい空・中間・深宇宙の3状態を localStorage 経由で作り、シルエットと発光の切り替わりを目視確認
3. **記録の非破壊** — UFO の記録を含むログを用意し、`spacetimer.totalFocusMin.v1` を削除した状態で読み込んで、総距離が NaN にならないことを確認（最も危険な箇所）
4. **流星群** — 発生間隔を一時的に短縮した版で描画し、放射状に流れることを確認
5. **既存機能の非破壊** — タイマー動作、休憩への遷移、ログ表示が従来通りであること

localStorage で状態を作る際は、アプリ自身の保存処理に上書きされるため、`Storage.prototype.setItem` を無効化してからリロードする必要がある。

## 11. 想定される失敗と対処

| リスク | 対処 |
|---|---|
| 集計処理の NaN | 7.2 で明示的に防御。検証項目3で確認 |
| 星空が変わってしまう | 4.6 のとおり乱数源を分離 |
| 放置で記録が増える | 4.5 のとおり `state.running` で制御 |
| 演出が騒がしくなる | 7.1 で彗星の反復を停止。頻度は定数で調整可能に |
| 描画負荷の増加 | 進行中イベントは同時に数個。既存の 220 個の星の描画に比べ影響は小さい |
